RELATIONSHIPS (Using UML Relationship Types):

1. Role ↔ User (Association)
   - One Role can have many Users
   - Many Users belong to one Role

2. User ↔ Address (Association)
   - One User can have many Addresses
   - Many Addresses belong to one User

3. User ↔ Order (Association)
   - One User can place many Orders
   - Many Orders are placed by one User

4. User ↔ Review (Association)
   - One User can write many Reviews
   - Many Reviews are written by one User

5. User ↔ Wishlist (Association)
   - One User can have many Wishlist items
   - Many Wishlist items belong to one User

6. User ↔ Cart (Association)
   - One User can have many Cart items
   - Many Cart items belong to one User

7. User ↔ ParentChild (Association)
   - One User (parent) can have many ParentChild relationships
   - One User (child) can have many ParentChild relationships

8. User ↔ AuditLog (Association)
   - One User can have many AuditLog entries
   - Many AuditLog entries are associated with one User

9. Category ↔ Product (Association)
   - One Category can have many Products
   - Many Products belong to one Category

10. Brand ↔ Product (Association)
    - One Brand can have many Products
    - Many Products belong to one Brand

11. Product ↔ ProductImage (Association)
    - One Product can have many ProductImages
    - Many ProductImages belong to one Product

12. Product ↔ ProductAttribute (Association)
    - One Product can have many ProductAttributes
    - Many ProductAttributes belong to one Product

13. Product ↔ OrderItem (Association)
    - One Product can be in many OrderItems
    - Many OrderItems reference one Product

14. Product ↔ Review (Association)
    - One Product can have many Reviews
    - Many Reviews are for one Product

15. Product ↔ Wishlist (Association)
    - One Product can be in many Wishlist items
    - Many Wishlist items reference one Product

16. Product ↔ Cart (Association)
    - One Product can be in many Cart items
    - Many Cart items reference one Product

17. OrderStatus ↔ Order (Association)
    - One OrderStatus can apply to many Orders
    - Many Orders have one OrderStatus

18. Address ↔ Order (Association)
    - One Address can be used in many Orders
    - Many Orders use one Address

19. Order ↔ OrderItem (Association)
    - One Order can have many OrderItems
    - Many OrderItems belong to one Order
